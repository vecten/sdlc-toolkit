# SDLC Toolkit

Config-driven SDLC skills for AI coding agents (Claude Code, Cursor). This repository is a single Claude Code plugin, distributed via the plugin marketplace flow.

## Repository structure

```
.claude-plugin/
  plugin.json                 # Claude Code plugin manifest
  marketplace.json            # Marketplace catalog (this repo is its own marketplace)
skills/
  <skill-name>/
    SKILL.md                  # Skill definition
references/
  skills-config-example.yaml  # Annotated schema for the per-workspace config
rules/
  <rule>.mdc                  # Rule templates installed into user workspaces
scripts/
  <script>.sh                 # Deterministic helpers invoked by skills
README.md                     # Public documentation
```

## How the plugin works

Every skill reads a per-workspace `skills-config.yaml` (generated by the `bootstrap-config` skill) instead of hardcoding team specifics. Skills are composable: `start-task` hands off to `finish-task`, `debug-sentry` hands off to `create-ticket` and `start-task`, and so on. See the composability diagram in `README.md`.

## Adding or changing a skill

1. Use the `generate-skill` skill (`/sdlc-toolkit:generate-skill`) to scaffold a new skill — it enforces the conventions below.
2. Each skill lives in `skills/<skill-name>/SKILL.md` with YAML frontmatter (`name`, `description`).
3. Conventions:
   - Read team/project specifics from `skills-config.yaml`; never hardcode tool vendors, ticket prefixes, channel names, or IDs. Use the `pm_tool` / `knowledge_base_tool` / `error_tracking_tool` config keys to stay tool-agnostic.
   - Extract deterministic multi-step logic into `scripts/` rather than prose instructions.
   - Document hand-offs to other skills explicitly.
   - Update the skill table and trigger examples in `README.md`.
4. If the config schema changes, update `references/skills-config-example.yaml` with annotated comments.

## Testing locally

Register this checkout as a local marketplace in Claude Code and install the plugin:

```
/plugin marketplace add ./
/plugin install sdlc-toolkit@vecten
```

Then smoke-test a skill (e.g. type `/sdlc-toolkit:bootstrap-config` in a test workspace).

Before opening a PR, run the same check CI runs (no model calls, no cost):

```
claude plugin validate . --strict
```

Bump `version` in `.claude-plugin/plugin.json` with each release. Installs from this marketplace stay on their cached copy until the version changes.
